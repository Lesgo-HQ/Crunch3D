Maintainers review contributions, triage issues, coordinate releases, and enforce the [code of conduct](CODE_OF_CONDUCT.md). These are project roles, not a claim about any individual's GitHub permission level.

Routine patches can be approved by a maintainer other than the author. Significant API, dependency, or algorithm changes should be discussed in an issue before implementation. Record the agreed scope and reasons there. Changes to licensing require the necessary copyright-holder permissions; a maintainer vote alone cannot relicense someone else's work.

For a release, review the diff, run the relevant checks in [CONTRIBUTING.md](CONTRIBUTING.md), document user-visible changes and known limitations, and check dependency licenses. If distributing binaries or containers, include the required notices and corresponding source for the shipped versions. Do not include user uploads, secrets, or private data in a release.

New maintainers can be proposed through an issue after sustained contributions and review participation. The existing team should agree on the role and record the outcome before repository permissions are changed.
